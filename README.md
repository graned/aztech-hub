# Aztech Hub Deployment

This directory contains two independently runnable projects and one unified deployment stack:

- `open-design/` provides the design/agent application.
- `open-code/` provides the Workspace Manager and official OpenCode Web service.
- Root `docker-compose.local.yml` and `docker-compose.prod.yml` run both projects behind one shared Caddy.

## Unified Domains

```text
design.aztech-hub.com     -> Open Design
workspace.aztech-hub.com  -> Workspace Manager
coding.aztech-hub.com     -> official OpenCode Web
```

Only the root Caddy publishes ports 80 and 443. MongoDB, Open Design, the Workspace Manager, and OpenCode remain private on internal Compose networks.

## Local Unified Stack

```sh
cp .env.local.example .env.local
cd open-code && ./scripts/setup-github-ssh.sh
cd .. && cp open-code/.env.ssh .env.ssh
scripts/start.sh local
```

Local URLs:

- `https://design.localhost`
- `http://workspace.localhost`
- `http://coding.localhost`

Open Design uses Caddy's local internal TLS certificate. Trust its CA only on a development workstation. The project-specific Compose files remain available when you want to run either project independently.

## DigitalOcean Deployment

Create `.env.prod` from `.env.prod.example`, point all three DNS records at the Droplet, verify the Droplet SSH host fingerprint, and allow TCP 22/80/443 plus UDP 443.

The deployment uses the GitHub SSH key generated by `open-code/scripts/setup-github-ssh.sh` unless overridden:

```sh
chmod 600 .env.prod
scripts/deploy-droplet.sh --ssh-key ~/.ssh/digitalocean root@203.0.113.10
```

The script installs Docker Engine, Buildx, and Compose, uploads both projects and root deployment files, transfers `.env.prod` and GitHub SSH material over SSH, validates Caddy, and starts the unified stack. The Droplet does not need Git.

To rerun the remote setup without a new upload:

```sh
ssh root@203.0.113.10
sudo bash /opt/aztech-hub/scripts/setup-droplet.sh /opt/aztech-hub
```

Rebuilds reuse the existing project data volume names, preserving workspaces, MongoDB metadata, OpenCode state, and Open Design state. Do not use `docker compose down -v` for routine updates.

## Individual Projects

The project folders retain their own Compose files for isolated operation:

```sh
cd open-code
docker compose -f docker-compose.local.yml up -d --build
```

```sh
cd open-design
docker compose -f docker-compose.local.yml up -d --build
```

Those standalone production files each include their own Caddy and therefore must not be started simultaneously on the same host as the root unified production stack.
