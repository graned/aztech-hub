Acceptance criteria and how each was met
----------------------------------------
1) "prompt route returns typed success/error"
   submitPrompt returns { ok: true, sessionID } on success; structured 400
   (bad-request with issues) for missing/empty/over-long text or malformed
   IDs; 404 for missing session; wrapped upstream error (502) for failures.
   Verified by tests in handlers.test.ts "prompt route" and live build route
   /api/workspaces/[id]/sessions/[sessionId]/prompt.

2) "SSE route emits validated event envelopes and closes on AbortSignal"
   streamSessionEvents subscribes to OpenCode events for the session's
   directory, runs them through filterSessionEvents (zod-validated, filtered
   to the requested sessionID), and streams data-framed JSON via
   createEventStreamResponse, which listens to request.signal "abort" with a
   once listener, closes the controller, and removes the listener in finally.
   Verified by eventRelay.test.ts "createEventStreamResponse" (frames emitted,
   header content-type text/event-stream, abort closes after 1 frame) and
   handlers.test.ts "events route" (session filtering + 400/404).

3) "browser source contains no OPENCODE_URL or opencode:4096"
   conversation.tsx (the only consumer) uses fetch()/EventSource against
   /api/... routes only. grep over src/components finds no OPENCODE_URL /
   opencode:4096. OpenCode credentials base lives only behind services.
